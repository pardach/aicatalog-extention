# Phase 6 — durable single pending request and catalog browsing
Explicit user-confirmed publication is written before network send into CEP userData/PardachStudioPublication/pending-v1.json. Atomic no-overwrite hard-link requires a supported local filesystem. If disk save or recovery fails, new publication is blocked. No bearer token/password persisted; artwork, reservation ID, account ID and origin are stored locally with OS permissions (not encrypted; shared Windows account is not isolated). No automatic upload on restart. Reconnect same account ID/origin, query status or retry identical payload. If status not_found, do not assume safe to discard. Success removes pending file; failed cleanup retains it for exact recovery. Single outstanding batch only; drafts before confirm, cancellation of uncertain requests, upload byte progress and multi-batch queue remain future work. Catalog search by name/content/family, age and curated popularity; 30-item pages; authorized SVG save for Studio-owned files up to 1 MiB (hash verified), no direct Illustrator placement yet. No edit/delete or external provider downloads. Real CEP filesystem API/Windows hardlink, server integration, security and failure tests required.
